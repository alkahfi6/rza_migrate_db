# Extractor continuation and executable reports — 2026-11-05

Default execution (including double-click/no flags) selects profile `continue`, enabling per-object skip/preserve. Shared extractor configuration defaults to `SkipUnsupportedTables=true`. Explicit profile `strict` retains the prior incomplete-snapshot blocker; bootstrap and the legacy skip flag remain available. Unlike the previous table handling, continuation covers every local table/index render error, not only messages matching the unsupported-feature whitelist. Type/module skip reasons already feed the existing preserve/warnings path.

Good objects are written; failed object snapshots are retained when available. No SQL is invented for inaccessible/encrypted definitions. Skipped objects remain unmanaged in the existing manifest, so absence from extraction is not a deletion instruction. Existing checker apply/plan/CI and generator policies are unchanged, including the authoring-name checks. Extractor never generates or repairs migration history. Global connection/catalog read errors, unsafe filesystem identity collisions, and output failures remain fatal rather than publishing guessed results.

Every CLI run writes `out/get_object_summary.json` and readable `out/get_object_issues.txt` under the configured repository root. Text contains warnings with object names and reasons, a run error when applicable, or an explicit clean result. Reports are refreshed so a clean rerun does not show old failures. A report write failure returns nonzero. This is a diagnosis report, not an export of unavailable source SQL. Preview remains a separate offline formatting command with its existing failure exit policy.
