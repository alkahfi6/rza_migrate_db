**Ditemukan 5 penghapusan indeks eksplisit tanpa CREATE ulang pada file up yang sama, 28 DROP INDEX disertai CREATE ulang, dan 4 pengurangan panjang kolom pada arah up.** Ada pula 3 perubahan constraint berindeks dan 56 DROP TABLE yang dicatat terpisah.

## Scope dan cara membaca hasil

- Seluruh **5.126 file SQL** dibaca: **2.563 pasangan up/down**, tanpa pasangan hilang. Identitas checkout engine: `39836cf747e249b848e0c131c69283dac4c82164`; folder `bond-sqltrsretail-main/` berstatus untracked sehingga identitas isi corpus ditetapkan dengan hash di bawah, bukan dianggap bagian dari commit tersebut.
- `up` adalah perubahan maju yang tertulis di history. `down` digunakan untuk memeriksa definisi lama/rollback. Daftar ini membuktikan isi skrip, bukan bahwa skrip pernah berhasil dijalankan di database tertentu; tidak ada koneksi atau eksekusi SQL Server.
- Pencarian kandidat diperiksa dengan masking komentar/literal SQL yang mempertahankan baris, lalu perbandingan DDL up/down dan CREATE sebelumnya. Identitas tabel/indeks/kolom dibandingkan dengan casing asli. String pembentuk definisi procedure dan operasi tabel sementara di dalam procedure tidak dihitung sebagai perubahan skema deployment.
- Semua 33 DROP INDEX up memiliki definisi CREATE sebelumnya yang sama dengan CREATE pada rollback. Semua 4 shrink memiliki ukuran lama yang cocok antara baseline CREATE TABLE dan rollback. Penemuan luas pada kode executable untuk DROP INDEX, ALTER COLUMN, DROP_EXISTING, dan sp_rename tidak menyisakan kandidat yang belum diklasifikasi.
- Urutan mengikuti prefix migration pada nama file. Prefix bukan bukti waktu deployment. Penghapusan ber-IF EXISTS atau ALTER dengan precheck tetap bersyarat pada keadaan database.

- Tidak ada source atau perilaku engine yang diubah; `go test ./...`, hardening gate, `build_all.bat`, dan rilis binary tidak dijalankan karena pekerjaan ini hanya audit corpus dan dokumentasi hasil. Tidak ada klaim validasi runtime atau status deployment.
